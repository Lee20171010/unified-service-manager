# 产品需求与接入范围

本文件以用户在本任务中提供的最初需求全文，以及后续确认的架构、插件和 UI 决策为依据。它定义目标范围；插件协议见 [PLUGINS.md](PLUGINS.md)，已交付能力见 [HANDOFF.md](HANDOFF.md)，验证证据见 [VALIDATION.md](VALIDATION.md)。

## 产品目标

用 Web UI 或原生 Android App，在一个界面管理多台机器上的服务、应用与自建工具，并处理 Magpie 和 Flutter ServerBox 的 WebDAV 备份与恢复。两端操作能力 1:1，布局和前端技术可以不同。

中央 Application Layer 部署在 nas-host NAS 的 Docker Compose 中，负责业务逻辑、主机访问、插件、后台任务、日志和备份策略。客户端呈现状态、发起操作、显示结果。SessionsFold 的参考点是共用 Application Services。

## 套件与应用插件

增加 bili / billion-context、oc-codex-multi-auth 和一般 npm 包管理。受管对象统一覆盖常驻服务、套件／CLI、应用插件与一次性工具，按能力显示操作。记录主机、执行账号、安装范围、Node 环境、版本策略和宿主关系；安装版本与载入版本分开，升级不自动重启宿主。详见 [MANAGED-RESOURCES.md](MANAGED-RESOURCES.md)。

## 动态接入与插件

- 动态增加主机，并在任何已配置主机上增加多个服务或工具实例；同一应用可以有多个实例。
- 四类插件分别为服务管理、套件与应用插件管理、应用备份、备份存储。每个开发出的插件有独立目录、标识、版本、清单、文档及契约测试。
- 全新系统的已安装插件为空。我们开发的插件进入 Plugin 页面的可安装清单，用户明确 Install 后，才贡献服务类型、表单和操作。Web 与 Android 共用中央安装状态。
- 安装通用服务插件后，用户可为新工具配置命令或脚本、工作目录、参数、超时和状态解析。简单接入无需为每个工具编写代码插件；需要专用协议或解析时，可开发独立插件。
- 新增配置、安装符合协议的插件及支持的插件更新，不要求重建中央 Application 映像或两个客户端。
- 插件声明动作 ID、显示名称、参数和结果，由中央校验并执行。两端按同一声明呈现；工具的专用动作也必须在两端可用。
- Plugin Install 注册的是管理能力。升级或修改受管主机上的软件是另一个明确的操作，必须进入 Job Console。

## 操作体验

统一总览支持按主机、名称和状态查找，显示操作结果及可取得的版本信息。更新、启停、重启、工具执行、备份和恢复均有 Job Console：实时 stdout/stderr、执行中／成功／失败状态、错误、历史和完整日志。长任务在客户端离开后继续运行。

升级在同一个 Job Console 的 Shell／PTY 中以前台程序运行。用户实时查看输出并直接输入；输入交给当前前台程序，支持确认提示与 Ctrl+C。升级完成、失败或中断后回到 shell 提示符，可继续运行排错指令。Web 与 Android 都提供相同能力，并清楚显示主机、账号、前台程序及 shell 状态。

任务与终端工作阶段分别建模：升级退出后任务结果固定，后续 shell 指令及输出不改变该结果，也不追加到任务日志。终端合并输出标为 terminal。另开 SSH 仍可用于独立诊断；已有升级 Console 本身就支持 shell。

收起面板、切换页面与暂时断网保留中央终端，重连不重跑升级或重送输入。“结束 Shell”或 exit 结束会话；已结束的历史会话只能查看，需明确另开连接。升级有任务期限，返回 shell 后使用独立空闲期限。中央重启不自动恢复或重放命令。

Shell 通过中央认证后的 Terminal Gateway 使用已配置账号连接，保持 SSH 主机密钥验证；客户端不持有 SSH 私钥。自由 shell 操作具有该账号的实际权限，不自动提权。输入原文和后续 shell 输出不默认持久化；敏感提示需要远端无回显，避免凭证进入输出记录。

主机或服务详情可另开 Interactive SSH Terminal，用于手动排错；它与受管操作的 Job Console 分开。两端提供浅色、深色及跟随系统模式。Review 入口通过 tailnet 访问。

## 同步与范围边界

当前明确的同步相关工作是 Magpie、Flutter ServerBox 的 WebDAV 备份与恢复。Skill 的管理和同步继续由 Magpie 负责。此阶段不从“同步”推导出新的通用文件同步引擎、跨主机双向同步或冲突合并功能。

范围维持单管理员的服务／工具管理、插件接入、任务输出和配置备份恢复。排程、计费、公开插件市场、账号角色需有后续明确需求才加入。终端支持本次确认的 Shell／PTY 交互；全屏 TUI 兼容范围需另行验证。

## 验收与实现状态

1. 首批清单中的每个对象都在接入跟踪中，并明确支持的操作、待确认配置及验证状态；示范数据不能替代真实需求清单。
2. 前四项逐一验证升级、重启、启动、关闭、状态显示；自建工具按声明的实际动作验证，包括至少一种带参数的一次性工具动作。
3. 用新主机和清单之外的服务／工具验证动态接入，不修改核心注册代码、不重建客户端；通用配置与独立插件两条路径均需验证。
4. 所有操作在两端具有相同能力，并能看到中央产生的任务输出和结果。
5. 分别验证 Magpie 和 Flutter ServerBox 的备份与恢复，检查内容、格式、完整性和失败时的数据保留。
6. 验证空插件状态、手动安装、重启后保留安装状态、插件缺失时保留原有记录及历史。
7. 用隔离升级 fixture 验证输出、确认提示、发送输入后继续执行、中断、断线后重新接入、升级退出后返回 shell、执行排错不改写任务结果、会话结束后拒绝输入，以及两端相同的交互能力。另验证需要 PTY 的程序和敏感输入处理；实机验证单独记录。

当前 0.2.0 已有 Compose 管理、只读输出的 Job Console、设置快照备份和两个客户端；升级任务的交互输入、独立插件安装流程、上述四个应用插件及自建工具接入尚待实现。应用原生备份格式兼容性也尚待确认。功能实现、fixture 测试、实机测试与实际部署必须分别记录。

开发时使用隔离 fixture 或 demo；接入真实主机前确认具体目标授权。各项目的文档、安装来源和执行方式在开发其插件时核实，保留需求覆盖并明确记录尚未完成的部分。
