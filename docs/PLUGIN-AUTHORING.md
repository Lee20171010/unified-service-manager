# 插件开发与 UI 发布 · 0.6

Web 与 Android 均在「插件」页面提供创建、导入和导出。Application、Web、APK 升级至 0.6.0 后，支持范围内的后续插件发布无需重建镜像或客户端。导入内容保存在现有 data 持久化目录，不需要进入 Docker 或增加挂载。

[现成插件及默认操作](PLUGIN-CATALOG.md)列出支持环境。可创建服务、套件／CLI、扩充插件、一次性工具；无需先安装通用模板。

## 在 UI 建立插件

点击「建立插件」，填写独立 ID、显示名称、插件版本、作者和说明，再选择对象类型与管理方式：

| 对象类型 | 管理方式 | 提供的操作 |
| --- | --- | --- |
| 常驻服务 | Docker Compose | 状态、启动、停止、重启、升级 |
| 套件／CLI、扩充插件 | npm | 状态、安装、升级、卸载、环境检查 |
| 服务、套件、扩充插件、一次性工具 | 自定义命令 | 所填写的操作 |

Compose 填写远端已存在的项目绝对目录。每个插件有独立 ID、默认目录和生命周期；同一主机、同一目录共用操作锁。

npm 填写实际套件名称、使用者 prefix 或项目范围、安装目录、Node 和 npm CLI 绝对路径、远端版本（latest 或完整版本号）。插件版本与远端软件版本分别管理。默认路径是可编辑示例，须符合目标主机。安装 Unified 插件只启用管理功能；建立受管对象后，执行「安装软体」才会在远端安装 npm 套件。

扩充插件可填写兼容的宿主插件 ID（逗号分隔）；留空表示仅管理安装，不开放宿主绑定。安装与宿主绑定分开进行，绑定仍使用受管对象的登记／取消登记／验证流程。

自定义命令填写远端工作目录与需要的操作，留空的操作不会加入插件。可增加字段名、标签、默认值、必填与选项；`directory`、`identity` 是基础字段，最多再增加 22 个参数。例如 `mode` 字段对应 `"$UNIFIED_MODE"` 环境变量。工作目录和程序属于被管理主机；状态命令可输出 `active`、`stopped` 或 `{"status":"online","version":"1.2.3"}`。

点击「校验与预览」，检查完整参数、操作与将替换的版本，再「保存到可安装」。最后在卡片按 Install；建立受管对象并选择主机后才能执行操作。

## 从现有插件复制

服务／套件插件卡片提供「复制并自订」。客户端读取完整可用 manifest，保留参数、命令、npm 信息及宿主限制，清空 ID 并以 1.0.0 开始。填写新的 ID，在 JSON 编辑区调整内容，再校验、预览和保存。已存在的 ID 会被拒绝；原插件保留。需要更新同一插件时使用 JSON 导入与增加版本的流程。

Compose、npm 和命令驱动支持独立副本。备份应用和储存驱动使用专用接口，可导出 JSON 参考配置。

## 导入与分享

开发者可在自己的电脑编写 `plugin.json`，参考 [interface v1 示例](RUNTIME-0.3.md#package-authoring-without-a-core-rebuild) 或仓库 `plugins/`。每个插件建议独立文件夹并附 README，说明支持的环境、远端安装方式、权限、参数、命令副作用和测试方法。

在任一客户端选择「导入插件」，选择 JSON 文件或粘贴内容。服务器校验后预览，再保存到可安装。文件及服务器规范化 JSON 均限制为 128 KiB。JSON 的字段与类型须符合接口；ZIP、任意核心代码、自动依赖安装不属于此接口。

点击卡片「导出 JSON」，Web 下载文件，Android 选择系统保存位置。导出的是卡片对应的可用版本，包含命令定义和字段默认值。请勿把密码、私钥等凭据写入这些定义。主机账号、资源实例设置及安装状态不随插件导出。

## 更新和存储

- ID 保持不变；修改内容必须增加版本，如 `1.0.0` → `1.1.0`。
- 导入已存在 ID 的新版本会替换可安装目录项，预览会说明替换关系。安装版本及运行中任务保持原状，需在卡片手动 Update。
- 同一版本的内容不可覆盖。导入重复且相同的内容可安全重复保存。
- 更新安装版本前须等相关任务结束；已有回退、禁用、移除操作仍然适用。
- UI 文件：`/data/plugins/catalog/<id>/plugin.json`，按 ID 独立目录，分类来自 manifest 的 `category`。UI 文件优先于内建、GitHub 和旧挂载目录中同 ID 的定义。
- 已安装且带校验和的副本：`/data/plugins/packages/<id>/<version>/plugin.json`。可安装与已安装目录分离。
- 备份整个 data 目录会同时包含导入文件和安装记录。回退到 0.3 前保留 0.4 数据备份；0.3 不发现 UI 导入目录，但已安装 interface v1 副本格式兼容。

## 开发边界与测试

`compose`、`commands` 和 `npm` 是可复用执行驱动，Web 与 Android 都提供建立表单。Magpie、ServerBox、WebDAV 使用现有专用 ID；全新执行协议或备份格式需要扩展核心。命令使用所选 SSH 账号权限，插件不构成隔离沙箱。

先在 demo 验证表单、安装、资源创建和输出交互。demo 不执行真实命令；实际命令要在专用测试主机/目录验证成功、失败、参数引用和状态返回，不能把 demo 成功当成真实运行证明。中央回归测试 `bash scripts/test.sh`；Android `android/gradlew -p android :app:assembleDebug :app:testDebugUnitTest --max-workers=1`。

## 发布到官方 GitHub 目录 · 0.5

通用 Compose/npm/WebDAV 插件随镜像提供；特定软件插件从官方仓库的 catalog 取得。提交 plugins/<category>/<id>/plugin.json 与 README，增加版本并运行 scripts/build-github-catalog.py。提交生成的 index 和内容哈希 JSON，保留已发行的历史文件。经过源码／命令与隐私审核后发布；Application 下一次检查即可发现，用户明确 Install／更新才启用。目录和单个包分别限制 256 KiB／128 KiB，包下载校验 SHA-256、身份和目录说明。

第三方开发者可提交到此仓库审核，也可直接分享 JSON，由管理员通过 UI 匯入。当前不提供任意仓库 URL 或执行任意核心代码的入口。插件命令仍使用管理员选择的 SSH 身份；哈希验证保证下载内容匹配目录，不提供命令沙箱。
